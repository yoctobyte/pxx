# Nodisx recipes: the bootstrap userland, compiled by pxx

Nodisx is an installer ISO that compiles the system on the target. It ships
very little as binaries: the kernel, pxx and a boot loader, and a small set of
permissive tools (its `docs/bootstrap.md` has the list). This directory holds
the pxx side of that: for each tool, a pinned source and a recipe that pxx
builds on the target **with only pxx, a POSIX shell and toybox-level tools**:
no gcc, make or autoconf.

Each tool has three scripts:

| script | runs on | needs |
|---|---|---|
| `record.sh` | the build host, once | gcc, make, curl |
| `onsite.sh` | the target (copied into the recipe) | pxx, sh, zcat, tar, sha256sum |
| `test.sh` | the build host | bash or perl, for the tool's own suite |

`record.sh` writes `$NODISX_WORK/recipe/<tool>/`. That directory and the
tarballs in `$NODISX_WORK/dl` (`sources.lock`: name, sha256, URL) are what
goes on the ISO. Whatever a tool's own build would generate with a host
compiler (toybox's `generated/*.h`, what mksh's `Build.sh` decides by running
test programs) is **pre-generated by `record.sh` on the build host** and
travels in the recipe. Each `record.sh` says what it pre-generates. The
recipe's `RECIPE` file names the pxx commit it was recorded with.

```
export NODISX_WORK=/data/tmp/nodisx
tools/nodisx/toybox/record.sh && tools/nodisx/toybox/test.sh
tools/nodisx/mksh/record.sh   && tools/nodisx/mksh/test.sh
# on the target, from the ISO:
DL=/iso/dl PXX=pxx sh /iso/recipe/toybox/onsite.sh /tmp/tb /mnt/target
DL=/iso/dl PXX=pxx sh /iso/recipe/mksh/onsite.sh /tmp/mksh /mnt/target
```

## How the units are compiled

`pxx --emit-obj --function-sections --shared-runtime`. With
`--shared-runtime` an object leaves pxx's runtime out, and `--link` builds it
once (cached under `$XDG_CACHE_HOME`, else `~/.cache`; that directory must be
writable on the target) and links it first. That halves toybox's on-site
build (123 s against 251 s at `JOBS=3` on the build host), because most of a
unit's compile time was its own copy of the runtime. `--function-sections`
keeps the binary at its size (1.07 MB of text for toybox; 4.8 MB without
it). Without `--shared-runtime`, use `--function-sections` at least: default
objects each keep a private copy of the C library's state (locale, strtok,
rand), which broke toybox's UTF-8 tests
(`bug-a-default-emit-obj-objects-each-keep-private-crtl-state`).

## toybox 0.8.15 (0BSD)

`make defconfig` plus `CONFIG_GZIP` (which brings GUNZIP and ZCAT). 205
units. `test.sh` runs toybox's own suite on the pxx build: PASS is no
failure (the gcc build passes all 1604), plus a `tar --strip-components`
extraction compared file by file with GNU tar's. toybox's tar does not
decompress xz or bzip2 itself: `xzcat f.tar.xz | tar -x`, with xzcat from
xz-utils.

## mksh R59c (MirOS licence)

The POSIX shell. `Build.sh` needs `cc -E` and runs test programs, so it runs
once on the host with gcc; its `-D` flags and its four generated files
(`*.gen`, `signames.inc`) are the recipe. `test.sh` runs mksh's `check.t` on
the pxx build and on the gcc build and compares the failures: in a
non-interactive environment about 30 tests fail on both (no tty, history).
PASS is no failure the gcc build does not have.
