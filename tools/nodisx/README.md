# Nodisx recipes: the bootstrap userland, compiled by pxx

Nodisx is an installer ISO that compiles the system on the target. It ships
very little as binaries: the kernel, pxx and a boot loader, and a small set of
permissive tools (its `docs/bootstrap.md` has the list). This directory holds
the pxx side of that: for each tool, a pinned source and a recipe that pxx
builds on the target **with only pxx, a POSIX shell and toybox-level tools**:
no gcc, make or autoconf.

Each tool has three scripts:

| script | runs on | needs |
|---|---|---|
| `record.sh` | the build host, once | gcc, make, curl |
| `onsite.sh` | the target (copied into the recipe) | pxx, sh, zcat, tar, sha256sum |
| `test.sh` | the build host | bash or perl, for the tool's own suite |

`record.sh` writes `$NODISX_WORK/recipe/<tool>/`. That directory and the
tarballs in `$NODISX_WORK/dl` (`sources.lock`: name, sha256, URL) are what
goes on the ISO. Whatever a tool's own build would generate with a host
compiler (toybox's `generated/*.h`, what mksh's `Build.sh` decides by running
test programs) is **pre-generated by `record.sh` on the build host** and
travels in the recipe. Each `record.sh` says what it pre-generates. The
recipe's `RECIPE` file names the pxx commit it was recorded with.

```
export NODISX_WORK=/data/tmp/nodisx
tools/nodisx/toybox/record.sh && tools/nodisx/toybox/test.sh
tools/nodisx/mksh/record.sh   && tools/nodisx/mksh/test.sh
# on the target, from the ISO:
DL=/iso/dl PXX=pxx sh /iso/recipe/toybox/onsite.sh /tmp/tb /mnt/target
DL=/iso/dl PXX=pxx sh /iso/recipe/mksh/onsite.sh /tmp/mksh /mnt/target
```

## How the units are compiled

`pxx --emit-obj --function-sections --shared-runtime`. With
`--shared-runtime` an object leaves pxx's runtime out, and `--link` builds it
once (cached under `$XDG_CACHE_HOME`, else `~/.cache`; that directory must be
writable on the target) and links it first. That halves toybox's on-site
build (123 s against 251 s at `JOBS=3` on the build host), because most of a
unit's compile time was its own copy of the runtime. `--function-sections`
keeps the binary at its size (1.07 MB of text for toybox; 4.8 MB without
it). Without `--shared-runtime`, use `--function-sections` at least: default
objects each keep a private copy of the C library's state (locale, strtok,
rand), which broke toybox's UTF-8 tests
(`bug-a-default-emit-obj-objects-each-keep-private-crtl-state`).

## toybox 0.8.15 (0BSD)

`make defconfig` plus `CONFIG_GZIP` (which brings GUNZIP and ZCAT). 205
units. `test.sh` runs toybox's own suite on the pxx build: PASS is no
failure (the gcc build passes all 1604), plus a `tar --strip-components`
extraction compared file by file with GNU tar's. toybox's tar does not
decompress xz or bzip2 itself: `xzcat f.tar.xz | tar -x`, with xzcat from
xz-utils.

## mksh R59c (MirOS licence)

The POSIX shell. `Build.sh` needs `cc -E` and runs test programs, so it runs
once on the host with gcc; its `-D` flags and its four generated files
(`*.gen`, `signames.inc`) are the recipe. `test.sh` runs mksh's `check.t` on
the pxx build and on the gcc build and compares the failures: in a
non-interactive environment about 30 tests fail on both (no tty, history).
PASS is no failure the gcc build does not have.

## dosfstools 4.2 (GPL-3.0): mkfs.fat, fsck.fat, fatlabel

The EFI system partition. `configure` runs once on the host with gcc; its
`-D` list (`flags`), the per-program unit lists (`units`, from automake's
link lines) and the one file it generates, `src/version.h` (`gen.tar`), are
the recipe. `test.sh` runs dosfstools' own `make check` (reference FAT12/16/32
and Atari images, fsck repairs, labels) with the pxx binaries in place of the
gcc ones, and formats eight images with both builds under `--invariant`:
PASS is no suite failure and every image, and both programs' output,
identical to gcc's. Note the licence: GPL-3.0, unlike the rest so far.

## xz-utils 5.6.3 (0BSD; liblzma 0BSD): xz, unxz, xzcat

Built before anything that ships as `.tar.xz` (e2fsprogs, util-linux): its
own tarball is the upstream `.tar.gz`, so toybox's `zcat` unpacks it, and the
`xzcat` it installs unpacks the rest. Upstream checksums only, no
recompressed tarballs. Signed by Lasse Collin (the 5.6.0/5.6.1 backdoor
releases are long behind it).

`configure` and one `make V=1` run on the host; `lib/units-from-make.sh`
turns the make log into `units` (each object's directory, source and
`-D`/`-I` flags) and `link` (xz's objects, `liblzma.a` expanded), and
`config.h` travels in `gen.tar`. The compiler questions configure asks gcc
are answered as pxx's (`record.sh` says which: no `<immintrin.h>`,
`<cpuid.h>`, CLMUL or hand-written asm). Units compile `--threadsafe`:
liblzma's encoder threads are pthreads.

`test.sh`: xz's own `make check` on the pxx binary, every pinned `.tar.xz`
decompressed by both builds, and 14 compressions (presets 0-9e, `-T3`,
LZMA1, SHA-256 check, the x86 BCJ filter, on a tarball and on random data)
byte-identical to gcc's. Under `LC_ALL=C`: crtl has no `en_US` locale data,
so `xz -l` under `LANG=en_US` prints no digit grouping where glibc's does.
Speed: compressing is about 8x slower than gcc -O2's build (`-6` on 20 MB:
111 s against 14 s); decompressing a 37 MB tarball takes 2.5 s.

## bzip2 1.0.8 (bzip2 licence, BSD-style): bzip2, bunzip2, bzcat, bzip2recover

A plain Makefile, no configure, nothing generated. `record.sh` runs it once
with gcc and reads the 9 units and the two link lines from its log
(`libbz2.a` expanded). The Makefile compiles with `-c x.c` and no `-o`,
which `lib/units-from-make.sh` does not read, so `record.sh` has its own
short awk. The tarball is `.tar.gz`.

`test.sh`: bzip2's own `make test` on the pxx binary, then 12 compressions
(a tarball, random data, an empty file and zeros, at -1, -5 and -9)
byte-identical to gcc's and each read back by the other build. Also `-t`
on a good and a corrupt file, two concatenated streams, `bzip2recover` on
a truncated file, and every `.tar.bz2` download at hand, all compared with
gcc's builds.

## zstd 1.5.6 (BSD-3-Clause; dual GPL-2.0, used under BSD): zstd, unzstd, zstdcat

No configure: the Makefile's probes for zlib, lzma and lz4 are answered as
the target's (none of them: zstd reads and writes .zst only), the
hand-written `huf_decompress_amd64.S` is off (`ZSTD_NO_ASM`, it is gas), and
pthreads are on, so units compile with `--threadsafe` and `-T` works. 43
units, nothing generated, no gen.tar. `test.sh` runs zstd's own CLI suite
(`tests/playTests.sh`, datagen built by gcc) on the pxx build and the gcc
build, both must pass; then 27 compression cases (levels 1..19, `--ultra
-22`, `-T4`, `--long`, a trained dictionary) on a tarball, random data and
datagen output: every .zst byte-identical to gcc's and read back by both
builds. playTests' FIFO case needed crtl's `_POSIX_VERSION`.

## dhcpcd 10.5.2 (BSD-2-Clause): dhcpcd, its hook runner and three hooks

The DHCPv4/DHCPv6/IPv4LL/IPv6-RA client the installer brings the network
up with. dhcpcd has its own hand-written configure; `record.sh` runs it
once with the choices given explicitly, not probed from the build host:
`--without-udev` (no udev on Nodisx), `--without-openssl` (dhcpcd's own
md5/sha256/hmac), `--with-hooks= --with-eghooks=` (only 01-test,
20-resolv.conf and 30-hostname; configure would otherwise add an NTP or NIS
hook if the BUILD host has chronyd or ypbind), and
`--enable-privsep --privsepuser=_dhcpcd`.

**Privilege separation is on** (owner 2026-11-27: the packet parsers must
not run as root). Only a small root process keeps the privileged work:
routes, addresses and raw sockets. The DHCP/ARP/BPF parsing and the control
socket run as `_dhcpcd`, chrooted to its empty home `/var/lib/dhcpcd`,
under dhcpcd's seccomp filter. onsite.sh's install adds that user: without
it dhcpcd says "no such user" and runs every process as root. dhcpcd makes
`/var/db/dhcpcd` and `/var/run/dhcpcd` itself.
`test-privsep-rainyday.sh DESTDIR BUSYBOX RUMPNIC [KERNEL]` boots Rainyday
with the on-site busybox, rumpnic and dhcpcd, and the `_dhcpcd` account
onsite.sh installed in DESTDIR (it fails if there is none). dhcpcd takes
QEMU's lease itself, its hooks write resolv.conf, and the guest pings,
fetches a file and stops dhcpcd. It checks /proc: the dhcpcd processes run
as `_dhcpcd` at seccomp mode 2, except one root process titled
"[privileged proxy]". PASS on 2026-11-27, with Rainyday 179dfaa or later
(NETLINK_GENERIC). The work found these crtl gaps, now fixed: getifaddrs
was IPv4 only (SIOCGIFCONF) and missed an interface with no address yet.
It now reads rtnetlink as glibc does, AF_PACKET entries first, at both
widths. open_memstream had no position, so the hooks never ran. And the
seccomp UAPI headers were missing.

gen.tar holds config.h, the option definitions configure generates
(`src/dhcpcd-embedded.{c,h}`) and the two hook scripts made from `.in`
files. 40 units, one link. `.tar.xz`, so the xz recipe comes first.
`onsite.sh WORK [DESTDIR]` installs `sbin/dhcpcd`, `libexec/dhcpcd-run-hooks`,
`libexec/dhcpcd-hooks/` and `etc/dhcpcd.conf` (kept if present), creates
`var/lib/dhcpcd`, and adds `_dhcpcd` to `etc/passwd` and `etc/group` (and
`etc/shadow` if there is one) unless it is there, with the lowest id in
100..999 that neither file uses.

`test.sh` compares with gcc's build what runs without root: `--version`, the
usage text and an unknown-option error; `-V`, the whole option-definition
table, with an empty config, the shipped dhcpcd.conf and a config of
`define`/`define6`/`vendopt`/`encap`/`embed` blocks; and dhcpcd's own crypto
self-test (the RFC 2202 HMAC-MD5 and SHA-256 vectors) built by pxx. The
live lease is test-privsep-rainyday.sh's job, above.

What dhcpcd needed from pxx and crtl (found by compiling every unit with
`-nostdinc -I lib/crtl/include`, so nothing came from the host's headers):
`_Alignas` and `<stdalign.h>`, the `alias` attribute (and DCE keeping an
alias's static target), posix_spawn, the IPv6 neighbour-discovery and
generic-netlink headers, initstate/setstate, fgetpos/fsetpos, closefrom,
memset_explicit. Tickets: bug-c-alignas-is-read-as-a-call,
bug-c-the-alias-attribute-was-ignored, feature-crtl-the-libc-gaps-dhcpcd-found.

## dropbear 2026.94 (MIT): dropbear, dbclient, dropbearkey, scp

The configuration `tools/dropbear_pxx.py` proved under pxx: `--disable-zlib`
and no login records (utmp/wtmp/lastlog off), `CFLAGS=-Os`. libtommath keeps
its 64-bit digits with the `mode(TI)` 128-bit word. gen.tar holds config.h

(sntrup761 and ML-KEM hybrids included), 1 MiB each way, a pty session, scp
both ways with the stock client and with the pxx scp as the client, and the

`units-from-make.sh` keeps a directory stack now: dropbear links at the top
after its libtomcrypt/libtommath sub-makes, and the commands after `Leaving

output is byte-identical).
## curl 8.23.0 (curl licence, MIT-style) with mbedTLS 3.6.8 (Apache-2.0) and the Mozilla CA bundle

One recipe holds two trees, `mbedtls/` and `curl/`. mbedTLS's Makefile is
`.SILENT`, so its units come from a dry run (`make -n -B`); curl's come from
the libtool log. curl's configure runs once, against a staged mbedTLS:
- static; HTTP(S), FTP(S), FILE and WS(S) only;
- none of zlib, brotli, zstd, nghttp2/3, libidn2, libpsl, libssh;
- the threaded resolver, so every unit is `--threadsafe`;
- CA bundle `/etc/ssl/certs/ca-certificates.crt` and no CA directory.
gen.tar holds `curl_config.h`, `tool_ca_embed.c` and mbedTLS's
`mbedtls_config.h`. 589 units are recorded. curl links 247 objects (aesni.o among them): its
own, plus the libcurl and mbedTLS archive members a gcc `-Wl,-Map` link
pulled. The bundle is `cacert-2026-11-05.pem` from curl.se (checked
against its .sha256), installed at that path. `units-from-make.sh` now
keeps `-isystem` directories, written as `-I`: curl names mbedTLS's headers
that way, and without them the unit was compiled against the host's.

**AES-NI is on** (2026-11-27). mbedTLS's `aesni.c` is built from its
inline-asm path, the one gcc takes without `-maes`: SSE2 moves, logic, shifts
and shuffles, the AES-NI and PCLMULQDQ instructions written as `.byte`, and a
`call` into a helper inside the template. pxx encodes all of it as gas does
(feature-c-inline-asm-sse-and-aes-ni). mbedTLS checks cpuid at run time:
with AES-NI the self-test says "using AESNI" under pxx as under gcc, and
without it mbedTLS falls back to its table-based software AES, which is
exposed to cache-timing side channels. mbedTLS's benchmark on plexus:
AES-CBC-128 27 MB/s with AES-NI against 6 MB/s in software under pxx, and
AES-GCM-128 8.9 against 0.76 MB/s. gcc's AES-NI build does 240 and 70 MB/s.
The instructions are the same bytes, so the rest of the gap is pxx's code
around them.

`test.sh` runs a local server (`testserver.py`, stdlib: HTTP, and HTTPS with
an EC and an RSA certificate from a throwaway CA). It compares the pxx curl
with the gcc curl on 46 rows, and all must match:
- `-V`;
- file://;
- HTTP: GET, HEAD, ranges, chunked, redirects, POST, PUT and multipart
  uploads of a 3 MB random file, headers, cookies, auth, status codes,
  connection reuse, parallel transfers, a host name only /etc/hosts knows
  (curl answers `localhost` itself, so that one never reached the resolver:
  pxx curl could not resolve names until crtl's getaddrinfo learned
  /etc/hosts and DNS in b240f77f68), an unknown name (exit 6);
- HTTPS over TLS 1.2 and 1.3 with each certificate, and the refusals
  (exit 60);
- every one of the 118 certificates in the bundle, loaded by mbedTLS;
- mbedTLS's own self-test, built by pxx from the same units: AES, GCM, CCM,
  SHA-2/3, the DRBGs, RSA, ECP, x509; 295 passed lines, identical to gcc's.
`NODISX_NET=1` also fetches https://curl.se/ with the bundle.

Fixed in pxx for this recipe:
- an empty asm with `+r` operands (mbedTLS's constant-time barrier);
- numbered clobbers (`"0"`, `"1"`);
- `__builtin_ia32_pause`;
- `return a, b;`;
- crtl: `accept4`, `<linux/tcp.h>`, and the rest of Linux's TCP option
  numbers. Without TCP_FASTOPEN_CONNECT, curl's Fast Open was silently
  compiled out; the strict `-nostdinc` header check found it.

## sqlite 3.46.0 (public domain): sqlite3

pixix's build, unchanged:
- the version is the one `tools/install_lib_candidates.sh` pins;
- the flags are pixix's `lib/stage-userland.sh` ones:
  `-DSQLITE_THREADSAFE=0 -DSQLITE_OMIT_LOAD_EXTENSION -DHAVE_READLINE=0`;
- two units, the amalgamation and `shell.c`, compiled from inside the
  source directory so `__FILE__` holds no path.
pixix fetches the amalgamation .zip, which toybox cannot unpack, so the
recipe takes the release's autoconf .tar.gz. Its four sources are
byte-identical to the zip's; `test.sh` checks that again whenever the pinned
zip is in the download directory. Nothing is configured or generated.

`test.sh` runs the six scripts in `sql/` through the pxx build and a gcc
build with the same flags:
- SQL: all join kinds, triggers, upsert, RETURNING, STRICT, query plans;
- the built-in functions, casts, integer and real edge cases, printf, dates,
  JSON/JSONB;
- recursive CTEs, floating point summed 100,000 times, every window function;
- the shell's output modes, `.import`, `.dump` and `.sha3sum`;
- errors, savepoints and WAL;
- 200,000 rows with overflow pages, indexes and VACUUM on a small cache.
Output and exit status are identical, and so is every database file, the
12 MB bulk one included. Each build reads the other's database.

pxx's `long double` is double (bug-c-long-double-is-8-bytes-in-pxx-and-16-in-gcc).
sqlite notices at start-up and formats reals with its double-double code, as
it does wherever long double is double. The gcc reference is built with
`-DLONGDOUBLE_TYPE=double` so that it takes the same path. Against a stock
80-bit gcc build, the only difference the scripts found is past 17
significant digits: `printf('%!.20g', 0.1)` gives the exact digits under pxx
and one fewer under x87. pxx needed no changes for sqlite.

## Limine 12.11.1 (BSD-2-Clause): the `limine` tool; the boot loaders ship as binaries

pxx builds the host tool, `limine` (one C file: `bios-install`,
`enroll-config`). The boot loaders themselves are the release's own
binaries from the signed `limine-binary` tarball: limine-bios.sys, the
CD/PXE/UEFI-CD images, and BOOTX64/IA32/AA64/RISCV64/LOONGARCH64.EFI. The
signature was checked against Mintsuki's key 05D29860...ECA23821. Building
the loaders would take what neither the target nor pxx has:
- nasm: 35 files in nasm syntax (stage 1, the real/protected-mode entry,
  the EFI and menu thunks, SMP spin-up);
- a freestanding cross toolchain per port, with ld.lld or GNU ld and six
  linker scripts;
- objcopy (`-O binary` stages, ELF to PE for every .EFI);
- real-mode i386 code generation.
`record.sh` lists them. The third-party code inside those binaries is 0BSD,
MIT, BSD-2, Apache-2.0, CC0 and CC-BY-3.0 (no GPL: libfdt is used under
BSD-2). `3RDPARTY.md` and LICENSE are installed with them under
`share/doc/limine/`, as the licences require.

The binary tarball's `limine.c` is the source tarball's `host/limine.c` with
the version strings filled in. Its `limine-bios-hdd.h` holds the HDD stage-1
sectors. `test.sh` builds the tool with gcc from the same file and compares:
- the command line;
- `bios-install` on an MBR image and on a GPT image with a BIOS boot
  partition: the images are byte-identical, and changed;
- the refusals, which leave the image as it was: no partition table, and GPT
  without a BIOS boot partition;
- `enroll-config` on BOOTX64.EFI and BOOTAA64.EFI: identical files, and
  `--reset` restores the shipped file.
Booting an installed image is left to the Path B QEMU image.

## rumpnic (NetBSD drivers: BSD; Rainyday's parts: MIT)

## util-linux 2.40.2 (GPL-2.0; libblkid and libfdisk LGPL-2.1, libuuid BSD): sfdisk, fdisk, blkid

Upstream `.tar.xz`, unpacked with the xz recipe's `xzcat`. Installs
`sbin/{sfdisk,fdisk,blkid}`. The libraries they use (libfdisk, libblkid,
libsmartcols, libuuid, libcommon) are built static and linked in. configure
turns every program off except blkid and the fdisks, and uses none of the
optional outside libraries (ncurses, readline, systemd, udev, libmagic...),
so there is no cfdisk, which needs a curses.

`configure` and one `make V=1` run on the host. `gen.tar` holds the 5
generated sources (config.h and the libraries' public headers), and
`lib/units-from-make.sh` reads 193 units from the log. libtool adds two
shapes. A convenience library is unpacked into the archive being built
(`ar x` into `.libs/X.lax/libcommon.a/`), and two members with one name are
`ln`-ed to `ltN-NAME.o`; both are mapped back to the objects the compiler
wrote. pxx links objects, never archives, and libcommon and libuuid both
carry `lib/sha1.c` and `lib/md5.c`. So `record.sh` relinks each program
once with `-Wl,-t,-t`, and `TRACE=` keeps exactly the members gcc's ld
loaded. Units compile `--threadsafe`, as libuuid links `-lpthread` and keeps
its clock state in `__thread` variables.

`test.sh` runs util-linux's own test components for these programs
(`tests/run.sh blkid fdisk sfdisk libfdisk libsmartcols lib md5 sha1 uuid
partx`) on gcc's build and with the pxx sfdisk, fdisk and blkid in its place:
50 of 50 on both, the same 299 sub-results OK and the same 29 skipped. `make
check` itself will not start in this configuration: it wants
`test_ttyutils`, which `--disable-all-programs` does not build. It also
partitions six images from sfdisk scripts (GPT and DOS, the ids fixed, one
script that sfdisk refuses). The images are byte-identical to gcc's, and so
are `sfdisk -d/-l/-J/-V`, `fdisk -l` and `blkid -p` on them, with the same
exit status.

## The whole on-site build, on Rainyday

`test-onsite-rainyday.sh` is the acceptance check. It boots the Rainyday
kernel under QEMU with an initramfs that holds the ISO tree
(`mkiso-tree.sh`: pxx with its compiler/ and lib/ sources, every recorded
recipe, and the sha256-checked tarballs) and only two binaries, toybox and
mksh, both built by pxx through their recipes. There is no gcc, binutils,
make, python or busybox in the guest. The guest runs `onsite-all.sh` and
exports the installed tree over the second serial line. The same driver
then runs on the host with the same pxx and with PXX_NO_HOST_INCLUDE=1, so
neither side sees the host's headers or /etc/ld.so.cache. PASS means every
recipe built in the guest and every installed file is byte-identical to
the host's.
