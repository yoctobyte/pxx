# PXX 0.1.0-beta.1 — codename "Blaise"

PXX is a self-hosting compiler for the Pascal dialect of Free Pascal, written
from scratch. It has its own runtime library, its own ELF writer and its own
linker, so a compiled program is a finished static executable that needs no
`as`, `ld` or libc. The same backend also compiles **C** and **Nil Python**, a
Python-shaped language. This is the first beta: `0.x` means the language, the
ABI and the command line may still change between releases.

This release is **pin v441**.

**Active development is paused after this beta. We are looking for sponsors
to continue it.** What continued development would bring: memory-leak
hardening across every target, Nil Python maturity, and more platforms. If you
or your organisation would fund that, open an issue at
<https://github.com/yoctobyte/pxx/issues> titled "Sponsorship".

## Frontends

| Language | State in this release |
| --- | --- |
| **Pascal** | Solid. FPC's `objfpc` and Delphi modes: classes, interfaces, generics, managed strings, dynamic arrays, exceptions and threads. The compiler compiles itself to a byte-identical binary. FPC's own test suite: **427 pass, 0 fail**, 73 skipped and 50 auto-gated, out of 550 tests. |
| **C** | Solid. A C99-class dialect with common GNU extensions and PXX's own C runtime. **c-testsuite: 220 of 220** single-program tests pass on x86-64. The same 220, compiled for the ESP32-S3 and run under Espressif's QEMU with v425: 219 pass, 0 fail, 1 skip (`00187.c` needs a writable file system the test image does not mount). Real C programs, below, are checked against GCC's build of the same source. |
| **Nil Python** | **Best effort: the least mature frontend, with a real backlog.** CPython compatibility is not a goal of this beta. It compiles Python-shaped source ahead of time to a static binary. It is not CPython and does not run CPython's standard library: imports resolve to PXX's own implementations first, and several of those cover only part of the module they are named after. If a program depends on exact CPython behaviour, check it. |

A small BASIC frontend also exists. The Rust and Zig frontends are
experimental proofs of concept; do not build on them.

## Targets

- **x86-64 Linux** is the host and the only native target. The compiler
  self-hosts there, and it is the most heavily tested target.
- **i386, aarch64, arm32 and riscv32 Linux** are cross targets, run under
  **QEMU 10.2.1** in user mode. A one-line program in Pascal, C and Nil
  Python compiles and runs on each of them (checked with v425); Nil Python
  refuses riscv32 with a message that names the reason (no heap arena there).
- **wasm32** runs under wasmtime 48.0.1. It is the least tested cross target:
  its suites are run by hand, not continuously.
- **ESP32-S3 (Xtensa)**: real hardware. On one physical ESP32-S3 board
  (ESP-IDF v6.0.1), all 15 ESP32-S3 examples, built with pin v425, passed,
  including GPIO-edge and ADC programs that QEMU cannot exercise and two Nil
  Python programs. The peripheral units (GPIO, UART, ADC, PWM, I2C, SPI,
  stored settings, timers) are usable from Pascal and from Nil Python; I2C and
  SPI have been checked on the bus without a device attached, never against a
  real device.
- **ESP32-C3 (RISC-V)**: **QEMU only.** No C3 program has been run on a
  physical C3 board.
- This release has **no Windows, macOS or BSD target**.

## Demos

- **The examples showcase** (`docs/examples/index.md`): terminal and GTK
  Pascal applications, the Eliah IDE written in PXX, a chess engine, parallel
  programs, Nil Python programs, ESP32 programs, and a bootable minimal Linux
  system whose shell and compiler were built by PXX.
- **Real C programs, compiled unmodified** and checked against GCC's build of
  the same source (with v425): SQLite 3.46.0, Lua 5.4.7, zlib 1.3.1, cJSON 1.7.18,
  Duktape 2.7.0, QuickJS (quickjs-ng 0.9.0), the Tiny C Compiler,
  tiny-regex-c, ENet 1.3.18 and BusyBox 1.36.1.
- **BusyBox with no libc.** The BusyBox unity build (applets `cat` and `echo`
  as one translation unit) compiles to a **171,224-byte static executable**
  (measured with v425)
  with no dynamic section, no interpreter and no libc, and its output is
  byte-identical to a GCC build over 29 cases. A second route, 55 objects
  linked by PXX's own linker with no external `ld`, is byte-identical to GCC
  over 82 cases.
- **lekkerzeilen**, a separate project: a 3D sailing simulator on the real
  Dutch rivers, written in ordinary Python with SDL2 and OpenGL. **The same
  source compiles with PXX into one native binary, with sound, and runs.** It
  is **not yet as fast as CPython**. A frame rate there is a property of the
  scene, and the one measured scene is the `world/roofs` region (4 tiles),
  the scene the demo starts in: 1.89 fps under PXX against 37.1 fps under
  CPython 3.14.4 (median over 20-frame windows of 150-second runs, PXX runs
  interleaved and then the CPython run, audio and vsync on, one machine, one
  program at a time). It was taken with pin v416, not with this release, and
  other scenes behave very differently. No other lekkerzeilen frame rate is
  current.

## Known limits

- **BusyBox and the other C libraries are not included.** Their sources are
  fetched by you: `tools/install_lib_candidates.sh busybox` (and likewise
  `sqlite`, `lua`, `zlib`, …) fetches the pinned upstream commit into
  `library_candidates/`, which is not part of the release archive.
- **Memory leaks were treated as release blockers, and none caused by the
  compiler is known in this release.** A pre-release sweep re-ran all 164
  automated leak checks, 49 Pascal shapes on seven targets at `-O0` to `-O3`,
  threaded programs on four targets, and real programs (uforth, the Pascal
  examples, Lua 5.4), each beside a deliberate leak it had to catch. It found
  five compiler-caused leaks, all fixed in this release: `Dispose` did not
  finalize its pointee, `Finalize` of a fixed array released only the first
  element, `Dispose(F())` of a call result, and in Nil Python a rebound `for`
  target and a `lambda` passed as an argument. ESP networking under QEMU
  (10,000 HTTP requests, MQTT, NTP and a Pascal TCP loop) showed no growth.
  **Not measured: Wi-Fi on real hardware.** On the ESP32-C3, long network runs
  stall under QEMU in the emulated network card; that is not a leak. Details:
  `docs/reference/known-issues.md`.
- **One riscv32 row is unresolved.** `wait4()` leaves its `rusage` argument
  untouched on riscv32 in one test, but only ever under QEMU 8.2.2 on one
  test host; it does not reproduce under QEMU 10.2.1. Whether that is a PXX
  defect or an emulator gap has not been separated.
- **ESP bare-metal images run under QEMU only.** On a real ESP32-S3 a bare
  image faults on its first byte-sized memory access; use the ESP-IDF profile
  on hardware.
- **A few programs compile and silently give a wrong answer.** C `long double`
  is 8 bytes, not GCC's 16, and an initialised C `__thread` variable reads 0
  outside the main thread. The full list is `docs/reference/known-issues.md`.
- `-O2` is the default and the level the compiler proves on itself. `-O3` is
  experimental.
- Integer division by zero gives 0 on ESP and stops the program on desktop.
  That is by design: an embedded device keeps running.

## Fixed since the draft pin v425

- On ESP, an uncaught exception prints its message before the chip stops.
- C member access and subscripts on a pointer out of a comma, `?:` or `=`
  expression read the right field.
- C compound literals of an array type are accepted in every shape, including
  through array typedefs such as cglm's `mat4`.
- A designator with a function call in it, such as `a[Pick(i)].Free`, calls
  the function once.
- A recursive `pthread` mutex can be re-locked (SQLite with threads no longer
  hangs).
- The five memory leaks listed above.

## Install and verify

Unpack the archive, then:

```sh
./setup.sh                 # puts `pxx` on PATH, using the prebuilt host binary
pxx examples/primes/sieve.pas /tmp/sieve && /tmp/sieve
./selfcheck.sh             # the self-host fixed point, and the prebuilt binaries against MANIFEST.sha256
```

`RELEASE.md` in the archive describes its layout and how to rebuild
everything from the included source.

## Reporting bugs

Open an issue at <https://github.com/yoctobyte/pxx/issues> with the smallest
source file that shows the problem, the exact command you ran, what you
expected (GCC's output for C, FPC's for Pascal, CPython's for Nil Python) and
what you got, and the output of `pxx --doctor`. **Programs that compile and
quietly give a wrong answer are the most valuable reports.**

## Acknowledgments

This project stands on a long lineage of people who made Pascal what it is.

- **Niklaus Wirth** (1934–2024), who designed Pascal in 1970 — and Modula-2 and
  Oberon after it. A teaching language built for clarity and structure that turned
  out to be powerful enough to write compilers, operating systems, and this. The
  whole point of PXX is an inheritance of his.
- **Blaise Pascal** (1623–1662), mathematician and builder of one of the first
  mechanical calculators — the name the language, and this compiler, carry forward.
- **Anders Hejlsberg**, who wrote the Turbo Pascal compiler and was the chief
  architect of Delphi — and later of C# and TypeScript. Turbo Pascal put a fast,
  affordable compiler in front of a generation of programmers; Delphi showed how far
  Object Pascal could go. That craftsmanship is part of this language's DNA.
- The **Borland / Turbo Pascal / Delphi** heritage — the conventions, the IDE-driven
  RAD model, and the Object Pascal dialect this project deliberately stays close to.
- The **Free Pascal Compiler (FPC)** team and community — FPC is the seed that
  bootstrapped PXX (the first generation was compiled by FPC before it became
  self-hosting), and its dialect compatibility, conventions, and decades of ecosystem
  work are the shoulders this stands on directly.

PXX uses FPC only as the **bootstrap compiler** and follows FPC-compatible
language/naming conventions. Its runtime library, PCL widget set, and backends are
**written from scratch** — no FPC RTL or LCL (nor any Borland/Delphi) source is
copied or ported. The gratitude is for the language, the ideas, and the foundation —
not for lifted code.

Thank you, all of you.
